# Languages

The site is in French and English. Every page lives under `/{_locale}/`, with `_locale` restricted to the enabled locales (`fr`, `en`; `fr` is the default). Any other prefix is a 404.

- `/` is `LocaleRedirectController`: a 302 to the best match of `Accept-Language` among the enabled locales, `fr` when nothing matches, with `Vary: Accept-Language`.
- `templates/base.html.twig` sets `<html lang>`, the canonical link and one `hreflang` alternate per locale, plus `x-default` pointing to `/`. It builds them from the current route and its parameters, so a new page gets them without any code.
- User-facing text lives in `translations/messages.fr.yaml` and `messages.en.yaml`, never in a template. `tests/TranslationsTest.php` (part of `make check`) fails, naming the key, when a template uses a key a catalogue lacks, or when one catalogue has a key the other lacks.
- The locales are listed twice: `framework.enabled_locales` in `config/packages/translation.yaml` and `app.locales_pattern` in `config/services.yaml`, because a route requirement can't take an array parameter. A test keeps them equal.

## Decisions

- **The locale is in the URL, not in a cookie or the session.** The site is stateless (no session), pages stay cacheable, and each language has its own indexable address. A visitor who lands on `/` gets the browser's language once; the switch is a link.
- **302, not 301, from `/`.** The target depends on the request, so it must not be cached as permanent. `Vary: Accept-Language` keeps shared caches from serving one language to everyone.
- **Two checks, because they catch different things.** `debug:translation --only-missing` (run per locale from a Pest test) extracts the keys the templates use and fails, naming them, when a catalogue lacks one, even if both lack it. The parity test reads the two YAML files only and fails when a key exists in one language only, which covers keys used from PHP or built dynamically, where extraction can't see them.
